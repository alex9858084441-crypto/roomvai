# RoomVAI — архитектура

## Обзор системы

```
┌────────────────────────────────────────────────────────────┐
│                     Мобильное приложение                    │
│   (React Native + Expo — iOS / Android)                    │
│                                                            │
│   Камера/галерея → выбор стилей → отправка на backend      │
│   ← просмотр и сравнение сгенерированных вариантов         │
└───────────────────────────┬────────────────────────────────┘
                            │ HTTP (multipart/form-data, JSON)
┌───────────────────────────▼────────────────────────────────┐
│                       Backend API                           │
│                    (FastAPI, Python)                        │
│                                                            │
│   /styles      — список доступных стилей                   │
│   /generate    — приём фото, запуск генерации              │
│   /jobs/{id}   — статус асинхронной задачи генерации       │
└───────────┬──────────────────────────────┬────────────────┘
            │                              │
┌───────────▼──────────────┐  ┌───────────▼──────────────────┐
│   Очередь задач          │  │   Хранилище изображений       │
│   (asyncio / Celery)     │  │   (локальный диск / S3)       │
└───────────┬──────────────┘  └──────────────────────────────┘
            │
┌───────────▼────────────────────────────────────────────────┐
│                   ML / AI модуль                            │
│                                                            │
│   1. ControlNet (seg/depth/normal) — фиксирует геометрию   │
│   2. Stable Diffusion img2img — рестайлинг по промпту      │
│   3. Постобработка (апскейл, цветокоррекция)               │
└────────────────────────────────────────────────────────────┘
```

## Поток генерации (пайплайн)

1. Пользователь делает фото помещения в приложении.
2. Приложение отправляет фото + выбранные стили на `POST /generate`.
3. Backend:
   - валидирует и сохраняет изображение;
   - создаёт асинхронную задачу (job);
   - возвращает `job_id`.
4. ML-модуль для каждого стиля:
   - извлекает структурный контроль (карта глубины/сегментация) через ControlNet;
   - запускает Stable Diffusion img2img с промптом стиля;
   - сохраняет результат.
5. Приложение опрашивает `GET /jobs/{id}` (или слушает WebSocket) и показывает прогресс.
6. Готовые изображения отдаются по URL, пользователь может сравнить их с оригиналом.

## Зачем ControlNet

Чистый img2img «плавит» геометрию комнаты — стены и проёмы искажаются. ControlNet передаёт структурный сигнал (глубина, сегментация, границы), поэтому результат повторяет **реальную планировку** помещения, меняя лишь отделку и мебель.

### Типы контрольного сигнала (`ML_CONTROL_TYPE`)

- **depth** — карта глубины (MiDaS / Intel dpt-hybrid-midas). Сохраняет объём и перспективу помещения. Значение по умолчанию.
- **canny** — границы Canny (OpenCV). Жёстко фиксирует контуры стен, дверных проёмов, мебели. Хорош для чётких линий.
- **seg** — семантическая сегментация (OneFormer, ADE20K). Группирует зоны в блоки; устойчиво, но менее детально.

Контрольный сигнал вычисляется один раз на задачу и переиспользуется для всех запрошенных стилей.

## Технологический выбор

| Компонент      | Выбор                          | Почему                                        |
| -------------- | ------------------------------ | --------------------------------------------- |
| Mobile         | React Native + Expo            | Один кодбейс для iOS/Android, быстрый старт    |
| Backend API    | FastAPI                         | Async, авто-документация, экосистема Python ML |
| ML             | Stable Diffusion + ControlNet  | SOTA для img2img с сохранением структуры       |
| Очередь        | Celery + Redis (позже)         | Тяжёлые задачи генерации не блокируют API      |

## Режимы генерации (`ML_MODE`)

- **mock** — плейсхолдеры без нейросети. Для разработки UI и тестов; не требует тяжёлых зависимостей.
- **sd** — реальная генерация через Stable Diffusion + ControlNet. Требует `torch`, `diffusers`, `transformers` (см. `requirements-ml.txt`). Генерация запускается в пуле потоков, чтобы не блокировать event loop FastAPI.

## Развёртывание (Docker)

- `Dockerfile` — multistage: target `base` (mock) и `ml` (реальная генерация).
- `docker-compose.yml` — поднимает backend + Redis. Redis зарезервирован под будущую очередь Celery.

## Соображения безопасности и приватности

- Загружаемые фото — приватные данные; хранить с ограниченным доступом, удалять по TTL.
- Rate limiting на эндпоинты генерации.
- В будущем — аутентификация пользователей и водяные знаки на превью.
